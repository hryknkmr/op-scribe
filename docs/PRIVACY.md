# 公開してよい情報・いけない情報

op-scribe は公開リポジトリで管理する前提で作っています。守るべき境界は 2 つあります。

1. **リポジトリ境界**: git に入れて GitHub に push してよいもの
2. **送信境界**: 拡張が記録したデータのうち、ブラウザの外（送信先・クリップボード・ファイル）に出してよいもの

## 1. リポジトリ境界

| 区分 | 例 | 置き場所 | 公開 |
| --- | --- | --- | --- |
| 拡張のソース・テスト・ドキュメント | `shared/` `content/` `tests/` | リポジトリ | ✅ |
| テスト用のダミー値 | `example.com`、`*.invalid`、架空の電話番号、テスト用カード番号 | リポジトリ | ✅ |
| 汎用の検出パターン | メール・電話・トークン形式の正規表現 | `shared/sanitize.js`、`scripts/pii-guard.patterns.txt` | ✅ |
| 社名・部署名・製品コードネーム・人名 | — | `scripts/pii-guard.patterns.local.txt`（gitignore）と拡張の設定画面 | ❌ |
| 社内・検証環境のホスト名、URL | — | 拡張の設定画面（ブラウザ内） | ❌ |
| 送信先 URL、認証トークン | — | 拡張の設定画面（ブラウザ内） / `.env`（gitignore） | ❌ |
| 実サイトでの操作記録 | `*.opscribe.json`、`recordings/` | ローカルのみ（gitignore） | ❌ |
| コミットの author / committer | — | `users.noreply.github.com` と、許可した名前のみ | — |

ポイント:

- **denylist に社名を書いて公開しない**。「何を隠しているか」自体が情報になります。社名などはローカルの
  `scripts/pii-guard.patterns.local.txt` に書きます（書き方は `pii-guard.patterns.local.example.txt`）。
- テストやドキュメントの例には、予約済みのドメイン（`example.com` / `*.invalid` / `*.test`）だけを使います。
  ガードはそれ以外のメールアドレスを検出して止めます。
- トークン形式の値はテスト内で文字列連結して組み立て、リポジトリに完成形を残しません。

### 3 段の遮断

| 段 | 仕組み | 回避 |
| --- | --- | --- |
| commit | `.githooks/pre-commit`（identity・staged 内容・unit test）、`commit-msg` | `PII_GUARD_SKIP=1` で一時回避可 |
| push | `.githooks/pre-push`（push 範囲の各コミットの追加行とコミットメッセージ、identity、author/committer の名前） | 同上 |
| merge | `.github/workflows/pii-guard.yml`（全 tracked ファイル、範囲内の**各コミット**の追加行とコミットメッセージ、author/committer の email と名前。全ブランチの push でも動く。範囲は PR ではその PR のコミット、push では root からの全履歴。ただし名前は、通常は push で増えたコミットだけを見る（push 前のコミットが取れないときは、main 以外は main から先、main は全履歴を見る。全履歴では例外の 2 件が検出されて失敗する）。main の古いコミット 2 件は例外として以前の名前を残している。#20） | required check にすれば回避できない（今のプランの private リポジトリでは設定できないので、公開時に設定する。#20） |

CI にはローカル denylist が無いため、CI が見るのは汎用パターンだけです。author/committer の**名前**は許可した値だけを通します。push で見るのは、通常はその push で増えたコミットだけです（表示名を変える前のコミットが残っているため。#20 で履歴は書き換えないと決めました。push 前のコミットが取れないときの範囲は上の表のとおりです）。社名などの検出はローカル hooks
が担うので、**clone したら最初に `pnpm setup-hooks` と local denylist の配置**を行ってください。

## 2. 送信境界（拡張が記録するデータ）

原則: **記録した時点で伏せる。伏せられないものは残さない。外に出す直前に、伏せる処理とは別の判定でもう一度検査する。**

扱いは、操作したホストが設定の「商用環境のホスト」に登録されているか（`commercial`）、いないか（`standard`）で変わります
（[ADR 0001](adr/0001-commercial-environment-policy.md)）。経路ごとの扱いと、それが構造で保証されるのか
できる限りの検出なのかは、[ADR 0003 の表](adr/0003-privacy-guarantee-matrix.md)が正本です。主なものは次のとおりです。

| 情報 | commercial | standard |
| --- | --- | --- |
| パスワード・認証コード・カード情報の入力 | `[[secret]]` `[[card]]`（ページ内で置換。拡張にも渡らない） | 同じ |
| メール・電話・氏名・住所などの入力欄 | 文字数だけ（ページ内で置換） | `[[email]]` `[[phone]]` `[[personal]]`（ページ内で置換） |
| 検索欄・選択肢 | 入力・選択した文字（パターンに当たる部分は伏せる） | 同じ |
| その他の自由入力 | 文字数だけ `[[text:12]]`（ページ内で置換） | 入力した文字（パターンに当たる部分は伏せる） |
| メモ（期待結果） | 書いた文字（パターンに当たる部分は伏せる） | 同じ |
| WebMCP ツールの引数 | 文字列は文字数だけ、数値は `[[number]]` | 入力欄と同じ規則で伏せる |
| ボタン・リンクなど操作した要素の名前 | 表示名をパターン検出＋指定語で置換し、1 行・80 字にする。本文・余白など操作対象でない要素は、作り手が宣言した名前（`aria-label`・`title`・`alt`）だけで、表示文字は読まない | 同じ |
| ホスト名 | 許可リスト外は別名 `site-1.invalid` | 同じ |
| URL のパス | 数字 ID・ハッシュ・`@ユーザー名`・指定語を区切りごと伏せる（Gherkin では `/orders/[[id]]`） | 同じ |
| URL のクエリ値 | すべて `[[v]]`（キーは残す） | 短い英数字で、名前が認証情報・個人情報を指さないものだけ残す |
| URL のフラグメント | 破棄 | SPA のルート（`#/settings`）だけ残す |
| URL の認証情報（`user:pass@`） | 破棄 | 同じ |
| 操作の直後にページが通知として宣言した領域の文（`role="status"`・`role="alert"`・`aria-live`） | 記録しない（ページでも読まない） | 操作の直後 5 秒間に変わった文だけ。パターンに当たる部分は伏せ、1 行・200 字にする |
| ページタイトル・上記以外のページ本文・スクリーンショット | 記録しない | 同じ |
| ページ側スクリプトが発火した操作（`isTrusted=false`） | 記録しない | 同じ |
| タブ ID、実ホスト名と別名の対応表、商用環境のホストの一覧 | ブラウザ内（session）にだけ保持 | 同じ |

- 商用かどうかは、content script の申告ではなく、拡張の service worker が Chrome の伝える送信元から判定し直します。
  商用のステップで自由入力が文字数だけになっていなければ、worker が `[[v]]` に置き換えます。
- 商用環境のホストと実名で記録してよいホストは、記録を始めたときの設定で固定します。
- 残した文と URL は、ページの文字列と伏せた箇所の並びで持ち、伏せ字を文字列に書き込みません（[FORMAT](FORMAT.md)）。
  `[[…]]` は Gherkin に描画するときだけ作り、Markdown では `‹メールアドレス›` のような和文で表示します。
  ページが書いた `[[…]]` は、伏せる前に `[ [` に崩すので、Gherkin の `[[…]]` は拡張が伏せたものだけです。

記録データは `chrome.storage.session` に置くため、ディスクには書かれず、ブラウザを閉じると消えます。

### 出口の検査

送信・Markdown/Gherkin のコピー・JSON 保存の **すべての出口**で、出ていく送信データ全体に 2 つの検査をかけ、
どちらかで 1 件でも見つかると中止し、どの項目かを表示します。

1. **構造の検査**（`shared/payload.js` の `checkPayload`）: 伏せる処理とは別の判定です。形の定義に無い欄・型・値、
   扱いの合わない値（secret の欄が伏せられていない、商用のステップの自由入力が残っている など）、
   記録から作り直したものと違う Gherkin を止めます。
2. **できる限りの検出**（`finalScan`）: パターン・指定語・**記録中に別名へ置き換えた実ホスト名**を探します。

Gherkin は出口のたびに記録から作り直すので、手で編集できません。送信は必ずプレビューを経由し、プレビューした文字列そのものを送ります。

同梱の受信サーバ（`tools/receiver.mjs`）も、受信時に同じ 2 つの検査を行い、引っかかったものは 422 で拒否します。
ただし拡張は、登録語と実ホスト名をブラウザの外に出しません。受信サーバでそれらも止めるには、
運用者が一覧ファイルを `OPSCRIBE_KEYWORDS_FILE=<ファイル> pnpm receiver` で渡します（1 行 1 語。ファイルはリポジトリに入れない）。
渡さなければ、受信サーバが探すのはパターンだけで、起動時にその旨を警告します。

### オンデバイス AI

再現手順の文章化に使う Gemini Nano（Prompt API）は端末内で動き、入力は伏せた後の手順だけです。
出力は「入力に無い URL・伏せ字を含まない」「最終検査を通る」ことを確認してから採用し、満たさなければ
テンプレート出力に切り替えます。Gherkin は AI を通さず記録から機械的に作ります。

## 既知の限界

- 人名やユーザー名が**ボタン・リンクの表示名**に出るサイト（例: ヘッダーのアカウントメニュー）は、
  パターンでは検出できません。「必ず伏せる語」に登録するか、該当ステップを操作ログから削除してください。
- 「商用環境のホスト」に登録していないホストの自由入力は、パターンに当てはまらない個人情報（例: 自由記述の住所の一部）を
  残す可能性があります。本番のホストは必ず登録してください。検証環境に本物のデータがある場合も同じです。
- 商用環境の URL のパスは、まだ standard と同じ規則です（ADR 0003 の U5。許可の形だけを残す規則は後の変更で入れます）。
- 記録対象のページ自身は、同じページ上の WebMCP ツール経由でそのサイト分の（伏せた後の）手順と、そのサイトで足したメモを読めます。
  他サイトのステップ、サイドパネルで書いたメモ、全体の件数、記録の ID は返しません（ADR 0003 の W8）。
  応答の中の別名は応答ごとに `site-1.invalid` から付け直します。呼び出したサイトが別名なら、それが `site-1.invalid` です（記録の中の番号とは違うことがあります）。
  ただし、応答は返す前に記録全体の実ホスト名で検査して止めるので、ページは候補のホスト名を書いて応答が止まるかを見ることで、
  そのホストが記録にあるかを推測できます。
- ページのスクリプトは、ツール呼び出しや期待結果を記録に足せます。記録では `source: 'agent'`（Gherkin の `| source | agent |`）が付き、
  人の操作と区別できます。タブの遷移は、人の操作かページのスクリプトか見分けられないので `source: 'unknown'` で記録します。
  `user` 以外のステップはサイトごとに 100 件までで、それを超えた分は記録せず、人の操作を押し出しません（W7）。
  ただし、ページのスクリプトが `focus()`・`blur()`・`requestSubmit()` などを呼ぶとブラウザは人の操作と同じ扱いのイベントを出すので、
  ページはそれで `user` のステップを作り、上限を超えて人の操作を押し出せます（既知の限界。W7）。
- 再現手順（Markdown）を作った後にステップを削除・追加すると、作り直すか欄を空にするまで、送信・コピー・保存はできません。
  削除した内容が手順の文に残ったまま出ていくのを防ぐためです。
