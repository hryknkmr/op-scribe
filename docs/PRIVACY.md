# 公開してよい情報・いけない情報

op-scribe は公開リポジトリで管理する前提で作っています。守るべき境界は 2 つあります。

1. **リポジトリ境界**: git に入れて GitHub に push してよいもの
2. **送信境界**: 拡張が記録したデータのうち、ブラウザの外（送信先・クリップボード・ファイル）に出してよいもの

## 1. リポジトリ境界

| 区分 | 例 | 置き場所 | 公開 |
| --- | --- | --- | --- |
| 拡張のソース・テスト・ドキュメント | `shared/` `content/` `tests/` | リポジトリ | ✅ |
| テスト用のダミー値 | `example.com`、`*.invalid`、架空の電話番号、テスト用カード番号 | リポジトリ | ✅ |
| 汎用の検出パターン | メール・電話・トークン形式の正規表現 | `shared/sanitize.js`、`scripts/pii-guard.patterns.txt` | ✅ |
| 社名・部署名・製品コードネーム・人名 | — | `scripts/pii-guard.patterns.local.txt`（gitignore）と拡張の設定画面 | ❌ |
| 社内・検証環境のホスト名、URL | — | 拡張の設定画面（ブラウザ内） | ❌ |
| 送信先 URL、認証トークン | — | 拡張の設定画面（ブラウザ内） / `.env`（gitignore） | ❌ |
| 実サイトでの操作記録 | `*.opscribe.json`、`recordings/` | ローカルのみ（gitignore） | ❌ |
| コミットの author / committer | — | `users.noreply.github.com` のみ許可 | — |

ポイント:

- **denylist に社名を書いて公開しない**。「何を隠しているか」自体が情報になります。社名などはローカルの
  `scripts/pii-guard.patterns.local.txt` に書きます（書き方は `pii-guard.patterns.local.example.txt`）。
- テストやドキュメントの例には、予約済みのドメイン（`example.com` / `*.invalid` / `*.test`）だけを使います。
  ガードはそれ以外のメールアドレスを検出して止めます。
- トークン形式の値はテスト内で文字列連結して組み立て、リポジトリに完成形を残しません。

### 3 段の遮断

| 段 | 仕組み | 回避 |
| --- | --- | --- |
| commit | `.githooks/pre-commit`（identity・staged 内容・unit test）、`commit-msg` | `PII_GUARD_SKIP=1` で一時回避可 |
| push | `.githooks/pre-push`（push 範囲の追加行と identity） | 同上 |
| merge | `.github/workflows/pii-guard.yml`（全 tracked ファイルと PR の全コミット） | 回避不可。required check にする |

CI にはローカル denylist が無いため、CI が見るのは汎用パターンだけです。社名などの検出はローカル hooks
が担うので、**clone したら最初に `pnpm setup-hooks` と local denylist の配置**を行ってください。

## 2. 送信境界（拡張が記録するデータ）

方針（どの環境でも共通。商用環境だけはさらに厳格。[ADR 0001](adr/0001-commercial-environment-policy.md)）:

- **完全に伏せる**: 認証情報 — パスワード欄、クレジットカード情報、認証コード・ワンタイムコード、API キー・トークン・秘密鍵
- **一部だけ伏せる**: 連絡先と識別子 — メールアドレス、電話番号、ID（長い数字・16 進・UUID、URL 中の ID や `@ユーザー名`）、IP アドレス
- **そのまま残す**: それ以外（入力した文字、ボタン名・リンク名、選択肢）
- 「必ず伏せる語」に登録した語と、許可していないホスト名は、設定どおり伏せる
- 外に出す直前に、出ていく文字列全体をもう一度検査する
- **商用環境**（設定の「商用環境のホスト」に登録したホスト）での操作は、さらに次のとおり扱う。beta・staging など、登録していないホストには及ばない
  - 入力欄・テキストエリア・エディタの値は、メール欄・電話欄・ID 欄も含めて文字数だけ（`[[text:12]]`。パスワード・カードは全体を伏せる）。検索欄（`type="search"`・`role="searchbox"`・`role="search"` の中）と選択肢の値は残す
  - WebMCP の文字列の引数は、メール・電話・ID も含めて文字数だけ（認証情報・カードは全体を伏せる）
  - URL のクエリ値とパスの区切りは、英数字と `. _ -` だけの 24 文字以内なら残し、それ以外は `[[v]]`。フラグメントは SPA のルート（`#/settings`）とパラメータだけ残し、ほかは `[[v]]`。商用環境のページに書かれた URL も同じ
  - 利用者が書く期待結果（メモ）は、ほかの環境と同じ規則で伏せて残す
  - 商用環境かどうかは、操作したページのホストで判定する（ページの申告ではなく、Chrome が伝える送信元で判定し直す）。ホストの一覧は記録開始時のものを、記録が終わるまで使う

| 情報 | 記録時の扱い | 外に出るもの |
| --- | --- | --- |
| パスワード・認証コード・カード情報・API キー・マイナンバーや社会保障番号の入力 | ページ内で即置換（拡張にも渡らない） | `[[secret]]` `[[card]]` |
| 文中のトークン・API キー・秘密鍵・32 文字以上の英数混在文字列 | 置換 | `[[secret]]` |
| メールアドレス（入力欄・文中・URL。英字以外を含むものも） | 一部を伏せる。メール欄・電話欄は、値全体が 1 つのアドレス・番号のときだけ一部を残す。何も認識できない値は全体の先頭と末尾だけ残し、ほかの規則に当たる部分を含む値は全体を伏せる | `s***@e***.com`、`s*****e`、`[[masked]]` |
| 電話番号 | 末尾 4 桁だけ残す | `***-****-5678` |
| ID（7 桁以上の数字、16 進、UUID、URL 中の ID、口座番号・IBAN・旅券番号などの欄） | 先頭と末尾だけ残す | `12****78`、`/orders/12**56` |
| URL の `@ユーザー名`、ユーザー名欄（`autocomplete="username"`、`username` などの名前） | 先頭と末尾だけ残す | `/@s*****e`、`ta**_y` |
| IP アドレス | IPv4 は前半 2 つ、IPv6 は先頭の 1 つだけ残す | `192.168.*.*`、`fd00:*:*` |
| その他の入力（自由入力・選択肢） | そのまま（上の規則に当たる部分だけ伏せる）。商用環境では自由入力は文字数だけ（検索欄・選択肢は残す） | 入力した文字、`[[text:12]]` |
| ボタン・リンクの表示名 | そのまま（同上）、80 字で切る | 表示名 |
| ホスト名 | 許可リスト外は別名に置換。入力値や表示名の中に書かれた URL（`//host` を含む）と、別名にしたホストの名前も同じ規則で伏せる | `site-1.invalid` |
| URL のクエリ | 値は残す。`token` `code` `key` `session` `auth` `state` `pin` `credential` など、入力欄で認証情報とみなす名前のキーの値は伏せる。`id` `user_id` などのキーの値と ID の形の値は先頭と末尾だけ残す | `?q=週末&token=[[secret]]&id=ab******56` |
| URL のフラグメント | パスと同じ規則（SPA のルートは読める形で残す）。`#access_token=…` や `#/route?code=…` のようなパラメータはクエリと同じ規則 | `#/settings`、`#code=[[secret]]` |
| 商用環境の URL の値（クエリ値・パスの区切り・フラグメント） | 短い英数字（`. _ -` を含む 24 文字以内）だけ残す。4 重以上にエンコードされた値は、どの環境でも全体を伏せる | `?q=shoes&ref=[[v]]`、`/items/[[v]]` |
| URL の認証情報（`user:pass@`） | 破棄 | — |
| ページタイトル・ページ本文 | 記録しない | — |
| スクリーンショット | 撮らない | — |
| ページ側スクリプトが発火した操作（`isTrusted=false`） | 記録しない | — |
| WebMCP ツールの引数 | 入力欄と同じ規則。`otp` `pin` `token` `csrf` などのキーは数値でも伏せる。商用環境では文字列は文字数だけ | `{"q":"shoes","otp":"[[secret]]"}`、`{"q":"[[text:5]]"}` |
| タブ ID、実ホスト名と別名の対応表 | ブラウザ内（session）にだけ保持 | — |

### 何を必ず伏せるか（保証の範囲）

伏せ方はパターン（規則）によるので、すべてを見分けることはできません。どこまでを保証するかは、手がかりの強さで決めています。

| 手がかり | 扱い |
| --- | --- |
| 欄の種類・名前やキーの名前（`type="password"`、`autocomplete`、`token` `otp` `user_id` `email` などの名前。表記の揺れ `orderID` `api_key` `newpassword` を含む） | **必ず伏せる**。入力欄・URL のパラメータ・WebMCP の引数・最終検査で同じ判定（`classifyKey`）を使う。名前が認証情報を指すキーの下は、入れ子の中まで全部伏せる |
| 値の形（秘密鍵、JWT、既知のトークン形式、Luhn を満たすカード番号、UUID、メールアドレス、IP アドレス、`otp=…` のように書かれた認証情報） | 対応している形は**必ず伏せる** |
| 選択式の欄（`select`・ラジオ・チェックボックス）で選んだ値 | ページが用意した選択肢なので**そのまま残す**（`country_id` で選んだ「Japan」など）。名前が認証情報・カードを指す欄（ワンタイムコード、カードの有効期限）だけは伏せる。名前が `session` だけの欄は残す |
| 自然な文の中の人名・住所・短い番号、サイト独自の呼び名 | 見分けられない。**既知の限界**（下）。気になる語は「必ず伏せる語」に登録する |

記録データは `chrome.storage.session` に置くため、ディスクには書かれず、ブラウザを閉じると消えます。

### 出口の最終検査

送信・Markdown/Gherkin のコピー・JSON 保存の **すべての出口**で、出ていく文字列全体を
`finalScan` にかけます。パターン・指定語・**記録中に別名へ置き換えた実ホスト名**・許可も別名化もしていないホストの URL・
URL（`/orders/…` や `?code=…` のように単独で書かれたものを含む）の中でまだ伏せるべき部分（ID・連絡先・認証パラメータ）・認証情報を指すキーの値のいずれかが 1 件でも
見つかると中止し、どの項目かを表示します。送信は必ずプレビューを経由し、プレビューした文字列そのものを送ります。

同梱の受信サーバ（`tools/receiver.mjs`）も受信時に同じ検査を行い、引っかかったものは 422 で拒否します。

### オンデバイス AI

再現手順の文章化に使う Gemini Nano（Prompt API）は端末内で動き、入力は伏せた後の手順だけです。
出力は「入力に無い URL・伏せ字を含まない」「最終検査を通る」ことを確認してから採用し、満たさなければ
テンプレート出力に切り替えます。Gherkin は AI を通さず記録から機械的に作ります。

## 既知の限界

- 人名やユーザー名が**ボタン・リンクの表示名**に出るサイト（例: ヘッダーのアカウントメニュー）は、
  パターンでは検出できません。「必ず伏せる語」に登録するか、該当ステップを操作ログから削除してください。
- 商用環境のホストを登録し忘れた、またはワイルドカードを誤ったホストは、商用環境として扱われません。beta・staging に本物の
  データが入っている場合も、商用環境の扱いにはなりません。
- 商用環境でも、検索欄・選択肢・ボタン名などに入った人名、短い英数字の URL の値（短い ID など）は残ります。
- 氏名・住所・顧客名などは、パターンでは見分けられないため **そのまま残ります**（方針どおり）。
  社外に送る前にプレビューで確認し、必要なら操作ログから削除するか「必ず伏せる語」に登録してください。
- 文中に `https://` なしで書かれたホスト名は、記録中に訪れたホストのものだけ別名に置き換えます。訪れていないホストの名前は
  そのまま残ります。
- 記録対象のページ自身は、同じページ上の WebMCP ツール経由でそのサイト分の（伏せた後の）手順を読めます。
  他サイトの手順は返しません。
