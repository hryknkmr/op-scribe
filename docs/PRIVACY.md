# 公開してよい情報・いけない情報

op-scribe は公開リポジトリで管理する前提で作っています。守るべき境界は 2 つあります。

1. **リポジトリ境界**: git に入れて GitHub に push してよいもの
2. **送信境界**: 拡張が記録したデータのうち、ブラウザの外（送信先・クリップボード・ファイル）に出してよいもの

## 1. リポジトリ境界

| 区分 | 例 | 置き場所 | 公開 |
| --- | --- | --- | --- |
| 拡張のソース・テスト・ドキュメント | `shared/` `content/` `tests/` | リポジトリ | ✅ |
| テスト用のダミー値 | `example.com`、`*.invalid`、架空の電話番号、テスト用カード番号 | リポジトリ | ✅ |
| 汎用の検出パターン | メール・電話・トークン形式の正規表現 | `shared/sanitize.js`、`scripts/pii-guard.patterns.txt` | ✅ |
| 社名・部署名・製品コードネーム・人名 | — | `scripts/pii-guard.patterns.local.txt`（gitignore）と拡張の設定画面 | ❌ |
| 社内・検証環境のホスト名、URL | — | 拡張の設定画面（ブラウザ内） | ❌ |
| 送信先 URL、認証トークン | — | 拡張の設定画面（ブラウザ内） / `.env`（gitignore） | ❌ |
| 実サイトでの操作記録 | `*.opscribe.json`、`recordings/` | ローカルのみ（gitignore） | ❌ |
| コミットの author / committer | — | `users.noreply.github.com` のみ許可 | — |

ポイント:

- **denylist に社名を書いて公開しない**。「何を隠しているか」自体が情報になります。社名などはローカルの
  `scripts/pii-guard.patterns.local.txt` に書きます（書き方は `pii-guard.patterns.local.example.txt`）。
- テストやドキュメントの例には、予約済みのドメイン（`example.com` / `*.invalid` / `*.test`）だけを使います。
  ガードはそれ以外のメールアドレスを検出して止めます。
- トークン形式の値はテスト内で文字列連結して組み立て、リポジトリに完成形を残しません。

### 3 段の遮断

| 段 | 仕組み | 回避 |
| --- | --- | --- |
| commit | `.githooks/pre-commit`（identity・staged 内容・unit test）、`commit-msg` | `PII_GUARD_SKIP=1` で一時回避可 |
| push | `.githooks/pre-push`（push 範囲の追加行と identity） | 同上 |
| merge | `.github/workflows/pii-guard.yml`（全 tracked ファイルと PR の全コミット） | 回避不可。required check にする |

CI にはローカル denylist が無いため、CI が見るのは汎用パターンだけです。社名などの検出はローカル hooks
が担うので、**clone したら最初に `pnpm setup-hooks` と local denylist の配置**を行ってください。

## 2. 送信境界（拡張が記録するデータ）

方針（1 段階のみ）:

- **完全に伏せる**: 認証情報 — パスワード欄、クレジットカード情報、認証コード・ワンタイムコード、API キー・トークン・秘密鍵
- **一部だけ伏せる**: 連絡先と識別子 — メールアドレス、電話番号、ID（長い数字・16 進・UUID、URL 中の ID や `@ユーザー名`）、IP アドレス
- **そのまま残す**: それ以外（入力した文字、画面タイトル、ボタン名・リンク名、選択肢、見出し）
- 「必ず伏せる語」に登録した語と、許可していないホスト名は、設定どおり伏せる
- 外に出す直前に、出ていく文字列全体をもう一度検査する

| 情報 | 記録時の扱い | 外に出るもの |
| --- | --- | --- |
| パスワード・認証コード・カード情報の入力 | ページ内で即置換（拡張にも渡らない） | `[[secret]]` `[[card]]` |
| 文中のトークン・API キー・秘密鍵・32 文字以上の英数混在文字列 | 置換 | `[[secret]]` |
| メールアドレス（入力欄・文中・URL） | 一部を伏せる | `s***@e***.com` |
| 電話番号 | 末尾 4 桁だけ残す | `***-****-5678` |
| ID（7 桁以上の数字、16 進、UUID、URL 中の ID） | 先頭と末尾だけ残す | `12****78`、`/orders/12**56` |
| URL の `@ユーザー名` | 先頭と末尾だけ残す | `/@s*****e` |
| IP アドレス | IPv4 は前半 2 つ、IPv6 は先頭の 1 つだけ残す | `192.168.*.*`、`fd00:*:*` |
| その他の入力（自由入力・選択肢） | そのまま（上の規則に当たる部分だけ伏せる） | 入力した文字 |
| ボタン・リンク・ラベル、画面タイトル、主見出し、見出し | そのまま（同上）、30〜80 字で切る。一覧・カード・記事の中のボタンや、カードのように並んだボタンは画面の構造に入れない | 表示名 |
| ホスト名 | 許可リスト外は別名に置換。操作後の変化・入力値・表示名の中に書かれた URL（`//host` を含む）と、別名にしたホストの名前も同じ規則で伏せる | `site-1.invalid` |
| URL のクエリ | 値は残す。`token` `code` `key` `session` `auth` `state` などのキーの値は伏せる | `?q=週末&token=[[secret]]` |
| URL のフラグメント | パスと同じ規則（SPA のルートは読める形で残す） | `#/settings` |
| URL の認証情報（`user:pass@`） | 破棄 | — |
| 一覧・カードの中身、記事やエディタ内の見出し | 画面の構造としては取らない（件数だけ） | `一覧（同じ形のリンク 32 件）` |
| ページ本文 | 画面の構造としては文字数だけ | `本文（約 4200 文字）` |
| 操作の直後にページが通知として宣言した領域（`role="status"`・`role="alert"`・`aria-live="polite"`/`"assertive"`）に現れた・一時的に表示された文字（5 秒間。操作の前から出ていた文字と、見えていない文字はできるだけ除く）。一覧の行や本文、class 名がトースト風なだけの要素やダイアログに現れた文字は記録しない | 上の規則で伏せ、1 行 160 字・それぞれ 8 行まで | 文字そのもの |
| スクリーンショット | 撮らない | — |
| ページ側スクリプトが発火した操作（`isTrusted=false`） | クリック・値の確定（`change`）・送信だけ記録し、主体を `script` とする。`input` だけを発火した値の変更は記録しない | — |
| WebMCP ツールの引数 | 入力欄と同じ規則。`otp` `pin` `token` などのキーは数値でも伏せる | `{"q":"shoes","otp":"[[secret]]"}` |
| タブ ID、実ホスト名と別名の対応表 | ブラウザ内（session）にだけ保持 | — |

記録データは `chrome.storage.session` に置くため、ディスクには書かれず、ブラウザを閉じると消えます。

### 出口の最終検査

送信・Markdown/Gherkin のコピー・JSON 保存の **すべての出口**で、出ていく文字列全体を
`finalScan` にかけます。パターン・指定語・**記録中に別名へ置き換えた実ホスト名**のいずれかが 1 件でも
見つかると中止し、どの項目かを表示します。送信は必ずプレビューを経由し、プレビューした文字列そのものを送ります。

同梱の受信サーバ（`tools/receiver.mjs`）も受信時に同じ検査を行い、引っかかったものは 422 で拒否します。

### オンデバイス AI

再現手順の文章化に使う Gemini Nano（Prompt API）は端末内で動き、入力は伏せた後の手順だけです。
出力は「入力に無い URL・伏せ字を含まない」「最終検査を通る」ことを確認してから採用し、満たさなければ
テンプレート出力に切り替えます。Gherkin は AI を通さず記録から機械的に作ります。

## 既知の限界

- **画面タイトル・主見出し**には、記事名や投稿者名が入ることがあります（例: 「記事タイトル｜投稿者名」）。
  パターンでは検出できないため、気になる語は「必ず伏せる語」に登録してください。
- 人名やユーザー名が**ボタン・リンクの表示名**に出るサイト（例: ヘッダーのアカウントメニュー）は、
  パターンでは検出できません。「必ず伏せる語」に登録するか、該当ステップを操作ログから削除してください。
- 氏名・住所・顧客名などは、パターンでは見分けられないため **そのまま残ります**（方針どおり）。
  社外に送る前にプレビューで確認し、必要なら操作ログから削除するか「必ず伏せる語」に登録してください。
- 文中に `https://` なしで書かれたホスト名は、記録中に訪れたホストのものだけ別名に置き換えます。訪れていないホストの名前は
  そのまま残ります。
- **操作の直後に変化した文字**には、自分が入力した文や他人の名前が入ることがあります。上の規則で伏せてありますが、
  氏名などはパターンでは見分けられません。送る前にプレビューで確認してください。
- **「見えている文字だけ読む」は、余計な文字を減らすための努力目標で、保証ではありません。** 描画されていて（非表示・透明・
  文字色が透明でない）、点より大きく、スクロールで画面に出せる位置に丸ごとあること（固定表示の要素は画面の中）で判定します。
  一部でも切り取られた文字のかたまりと、`clip-path` などで見える範囲を計算しない要素や、拡大縮小・回転した切り取り領域の中は
  読みません。それでも、背景と同じ色の文字や、他の要素に覆われた文字など、CSS で隠した文字を読むことはあります。iframe と
  Shadow DOM の中は読みません。外に出る文字を守るのは、上の伏せる規則と、出口ごとの最終検査です。そのため、ページから
  文字そのものとして外に出すのは、通知の領域の文（操作の結果）に絞っています。
- 区画や欄の名前には、`aria-label` などの読み上げ用の名前も使います（画面に出ていなくても）。ボタン名・リンク名と同じ扱いです。
- 画面の構造は 1 画面 150ms を目安に読み終えます。時間を超えたら、構造の数え上げはそこまでだけを使います（本文の文字数を
  数える処理など、途中で止められない処理は超えることがあります）。
- 操作で消えた文字は記録しません。消えた要素は DOM から外れていて、表示されていたかを確かめられないためです。
- WebMCP のツールで行った操作は、ツールの実行が終わってから記録されます。そのため、ツールの操作とその結果（遷移した画面や通知）は
  結び付けません。ツールの前の操作の結果に、ツールが起こした画面が入ることもあります。
- 記録対象のページ自身は、同じページ上の WebMCP ツール経由でそのサイト分の（伏せた後の）手順を読めます。
  他サイトの手順は返しません。
