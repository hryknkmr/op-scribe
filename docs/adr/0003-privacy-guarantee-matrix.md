# 0003. 伏せ方の保証の表（受け入れの表）

- 状態: 提案
- 日付: 2026-10-31
- 関係: [ADR 0001](0001-commercial-environment-policy.md)（商用環境だけ厳格）、[ADR 0002](0002-why-review-did-not-converge.md)（収束しなかった真因と対策）

## 目的

- 何を**構造で保証する**か、何を**できる限り見つける**か、何を**対象外**とするかを、経路ごとに 1 つに決めて固定します。
- 実装・テスト・レビューは、この表に照らします。
- 表を変えるときは、この ADR を改めます（オーナーの判断）。

## 言葉

- **環境**
  - `commercial`: 設定の「商用環境のホスト」に登録したホストでの操作。判定は Chrome が伝える送信元で、worker が行う。
    URL の値（ページの URL、文中の URL）は、操作したページが `commercial`、**または** その URL 自身のホストが登録されていれば `commercial` として扱う（ADR 0001）。
  - `standard`: それ以外（beta・staging など）。
- **扱い**（伏せた結果は、型の付いた値で持つ。文字列にするのは出力するときだけ）

| 扱い | 意味 | 出力の例 |
| --- | --- | --- |
| `redacted` | 全部伏せる | `[[secret]]`・`[[card]]`・`[[v]]`（形の許可リストを通らない値）・`[[url:invalid]]`（解析できない URL） |
| `length` | 文字数だけ残す | `[[text:12]]` |
| `partial` | 一部だけ残す | `s***@e***.com`・`***-****-5678`・`12****78` |
| `alias` | ホスト名を別名にする | `site-1.invalid` |
| `kept` | そのまま残す。ただし「できる限り」の検出はかける | 入力した文字 |
| `dropped` | 記録しない | — |

- **保証の強さ**
  - **構造**: 次のどれかで決まる。漏れは不具合（レビューでは BLOCKER または HIGH）。
    - 経路・欄の種類・キー名・解析した構造（`URL` の解析結果など）。
    - 残してよい形の**許可リスト**（それ以外はすべて伏せる）。
  - **できる限り**: 残す文の中を、伏せる形の**拒否リスト**（値の形のパターン）で探す。漏れは既知の限界（レビューでは MEDIUM。一覧に積んでまとめて対応する）。
  - **対象外**: 扱わない。下に書く。

## 表

### 入力の値

上から順に見て、**最初に当てはまった行**の扱いにする（1 つの欄が複数の行に当てはまっても、扱いは 1 つに決まる）。

| 経路 | commercial | standard | 強さ |
| --- | --- | --- | --- |
| パスワード欄、`autocomplete` が `one-time-code`・`current-password`・`new-password`・`cc-*` | `redacted` | `redacted` | 構造 |
| 欄の名前（name・id・ラベル・placeholder・aria-label）が認証情報・カードを指す（語彙は `classifyKey` の一覧。テストで固定） | `redacted` | `redacted` | 構造（一覧にある語と、その表記の揺れ: 大文字小文字・区切り・camelCase・末尾の数字・不可視文字・全角）。一覧に無い同義語はできる限り |
| 選択肢（`select`・ラジオ・チェックボックス・`range`・`color`） | `kept` | `kept` | 構造（残すこと）。中のパターンはできる限り |
| 検索欄（`type=search`・`role=searchbox`・`role=search` の中。マークアップだけで判定） | `kept` | `kept` | 構造（残すこと）。中のパターンはできる限り |
| メール欄・電話欄・ID 欄（`type`・`autocomplete`・名前で判定） | `length` | 値全体が 1 つのアドレス・番号なら `partial`、そうでなければ `redacted` | 構造（生の値を残さないこと）。`partial` と `redacted` のどちらになるかは値の形で決まる |
| そのほかの入力欄・テキストエリア・エディタ | `length` | `kept` | 構造（commercial）・できる限り（standard） |

### そのほかの経路

入力の値と同じく、上から順に見て**最初に当てはまった行**の扱いにする。送信データの欄は `buildPayload` の許可リストで決まり、この表のどれかの行に必ず当たる（新しい欄を足すときは、先にこの表に行を足す）。

| 経路 | commercial | standard | 強さ |
| --- | --- | --- | --- |
| WebMCP の引数（キーが認証情報・カードを指す、またはその下） | `redacted` | `redacted` | 構造 |
| WebMCP の引数（そのほかの文字列・数値） | `length` | `kept` | 構造（commercial）・できる限り（standard） |
| WebMCP の引数（真偽値・`null`） | `kept` | `kept` | 構造 |
| WebMCP の引数（オブジェクト・配列） | 中の値ごとにこの表を当てる。深さ 3・配列 10 件・キー 20 個を超えた分は `dropped`。キー名は `kept`（伏せる対象を含めば `redacted`） | 同じ | 構造（中の値と上限）・できる限り（キー名の中のパターン） |
| WebMCP のツール名（操作したツール、ページが公開したツールの一覧） | `kept`（80 字まで・50 件まで） | 同じ | できる限り |
| 利用者が書くメモ（期待結果） | `kept` | `kept` | できる限り |
| 操作した要素の名前、画面のタイトル | `kept`（80 字まで） | 同じ | できる限り |
| 決まった値の欄（ステップの種類・時刻・`ok`・`source`・`checked`・画面の種類と数） | `kept` | 同じ | 構造（型と列挙で検査し、合わなければ止める） |
| 要素の役割（`role`）・タグ名 | ARIA の役割と HTML のタグ名の一覧にあれば `kept`、無ければ `dropped` | 同じ | 構造（許可リスト） |
| キー入力 | 修飾キーと `Enter`・`Escape` の組み合わせなら `kept`、ほかは `dropped` | 同じ | 構造（許可リスト） |
| selector | 数字 3 桁以上・16 進・URL・`@`・エスケープ・伏せる対象を含めば `dropped`、ほかは `kept` | 同じ | できる限り（拒否リスト） |
| URL の値（ページの URL・遷移先・リンク先の `href`）の `user:pass@` | `dropped` | `dropped` | 構造 |
| URL の値のホスト（`URL` で解析できたもの） | 許可リストに無ければ `alias`。解析できなければ値全体を `[[url:invalid]]` | 同じ | 構造 |
| URL の値のパス・クエリ | 認証情報のキーは `redacted`。ほかは短い英数字（`. _ -` を含む 24 字まで）だけ `kept`（ID の形なら `partial`）、それ以外は `[[v]]` | 認証情報のキーは `redacted`、ID のキーと ID の形は `partial`、ほかは `kept` | 構造（commercial: 許可リスト）・キーは構造、値の中のパターンはできる限り（standard） |
| URL の値のフラグメント | SPA のルート（`#/` で始まり、`/` で区切った各部分がパスと同じ許可リストを通るもの）だけ `kept`。`?` 以降のパラメータと、ルートと判定できないフラグメントは `[[v]]`（ADR 0001） | パスと同じ | 構造（commercial: 許可リスト） |
| この表に無い経路・型 | `[[v]]`（`redacted`） | `kept` | 構造（commercial）・できる限り（standard） |

### 残す値の中にかける検査

上の表で `kept` または `partial` になった値（文字列）すべてに、上から順にかける。

| 検査 | 扱い | 強さ |
| --- | --- | --- |
| 登録語（必ず伏せる語） | 正規化したうえで、大文字小文字を区別せずに `redacted` | 構造（登録した語とその正規化形の完全一致） |
| 記録したホストの名前（URL でない書き方） | 訪れたホストの名前は `alias` | 構造（訪れたホスト）・対象外（訪れていないホスト） |
| 文の中に書かれた URL | 見つけたものは、ホストを `alias`、パス・クエリ・フラグメントを上の URL の値の規則で扱う（環境は、その値の環境と URL 自身のホストのどちらかが commercial なら commercial） | できる限り（URL を見つけること自体がパターンに頼るため） |
| メール・電話・カード番号・ID・IP・トークン | パターンで見つけたものを `partial` または `redacted` | できる限り（扱う書き方は下の「正規化」のあと） |

### 出口と受信

| 経路 | 扱い | 強さ |
| --- | --- | --- |
| 送信・コピー・保存の出口 | 送信データの形・型・扱いの印を、伏せる処理とは独立した判定で検査する。commercial の値は型の付いた扱い（`length`・`redacted` など）でなければ止める。文の中のパターンはもう一度探す | 構造（形と扱いの印）・できる限り（パターン） |
| Gherkin（commercial を含む記録） | 出口で記録から作り直す（手の編集は使わない） | 構造 |
| Gherkin（standard だけの記録） | 手の編集を `kept`。出口でパターンをもう一度探す | できる限り |
| 手で編集した Markdown（再現手順の欄） | `kept`。出口でパターンをもう一度探す | できる限り |
| AI が書いた文（#8 以降） | `kept`。出口でパターンをもう一度探す。記録のステップには書かない | できる限り |
| 受信サーバ | 出口と同じ構造の検査（同じ定義を使う）。知らない欄・型・方針の名前は拒否 | 構造 |

## 正規化（「できる限り」の検出の前に 1 回だけ）

- NFKC
- 書式文字（`\p{Cf}`）と異体字セレクタを取り除く
- 他の文字体系の数字を ASCII に
- ダッシュ類（`\p{Pd}`）を `-` に
- `%` を、解けるところまで 3 回解く（4 回以上は値ごと `[[v]]`）
- URL は `URL` で解析して書き直す

この後の文字列にない書き方（ここで吸収できない表記）は、できる限りの側です。

## 対象外

- iframe と Shadow DOM の中。スクリーンショット。
- 登録していない商用ホスト（登録漏れ）。本物のデータが入った beta・staging。
- 残す経路にある自然な文の中の人名・住所・顧客名（「必ず伏せる語」に登録する）。
- 訪れていないホストの、URL でない書き方の名前。

## 重大度と収束の条件（レビュー）

- **BLOCKER・HIGH**:
  - 「構造」の行の違反。
  - 「構造」の行の退行。「できる限り」の行でも、固定した資料（下）にある反例の退行。
  - サイトや層をまたぐ漏れ。
  - 出口・受信の構造の検査を迂回できる。
- **MEDIUM**:
  - 「できる限り」の行の検出漏れ（前に見つけていた書き方でも、固定した資料に無いものはここ）。既知の漏れの一覧に積む。
- **収束**: 次をすべて満たすこと。
  - この表の範囲で BLOCKER・HIGH が 0。
  - 回帰用の資料と、性質の検査がすべて通る。資料は、PR を始めた時点の `tests/fixtures/` の反例の集合で固定する。
  - レビューで出た新しい反例のうち、「構造」の行のものは、その PR で直して資料に足す。「できる限り」の行のものは既知の漏れの一覧に足し、その PR の収束の条件には入れない。
  - 最後の修正の後に、確認のラウンドを済ませている。
- **上限と停止**:
  - レビューは 1 つの PR につき最大 10 ラウンド。上限に達したら止め、オーナーに判断を返す（上限を上げる・既知の限界として受け入れる・止める）。
  - 指摘を直すにはこの表を変える必要があるときは、ラウンドを続けず、オーナーに返す。
