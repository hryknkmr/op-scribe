# 0003. 伏せ方の保証の表（受け入れの表）

- 状態: 採用（2026-10-31）。表の行のうち「実装」が ② のものは、作り直しの最初の PR（型の付いた値と出口の構造の検査）で入れた。③・④ の行は、それまで「暫定」の欄の扱いになる。
- 日付: 2026-10-31
- 関係: [ADR 0001](0001-commercial-environment-policy.md)（商用環境だけ厳格）、[ADR 0002](0002-why-review-did-not-converge.md)（収束しなかった真因と対策）

## 目的

- 何を**構造で保証する**か、何を**できる限り見つける**か、何を**対象外**とするかを、経路ごとに 1 つに決めて固定します。
- 実装・テスト・レビューは、この表に照らします。
- 表を変えるときは、この ADR を改めます（オーナーの判断）。

## 言葉

- **環境**
  - `commercial`: 設定の「商用環境のホスト」に登録したホストでの操作。worker が、Chrome が伝える送信元（タブのページとフレーム）のホストで判定する。どちらかが登録されていれば `commercial`。
  - URL の値（ページの URL、遷移先、リンク先）は、その値を持つステップが `commercial`、**または** その URL 自身のホストが登録されていれば `commercial` として扱う。後者（URL 自身のホストによる判定）は商用ホストの一覧に頼る「規則」で、worker が受け持つ。出口と受信サーバは一覧を持たないので、ステップの環境だけで URL の形を確かめる（E2）。
  - サイドパネルから足した URL の無いメモは、記録に `commercial` のステップが 1 つでもあれば `commercial`。
  - `standard`: それ以外（beta・staging など）。
  - 商用環境のホストと実名を出してよいホストは、記録を始めたときの設定で固定する。登録語（必ず伏せる語）は、足した分だけすぐ効く。
- **扱い**（伏せた結果は型の付いた値で持ち、文字列にするのは描画するときだけ）

| 扱い | 意味 | 型の付いた値 | 描画の例 |
| --- | --- | --- | --- |
| `redacted` | 全部伏せる | `{ treatment: 'redacted', kind: 'secret' }` | `[[secret]]`・`[[v]]` |
| `length` | 文字数だけ残す | `{ treatment: 'length', kind: 'text', length: 12 }` | `[[text:12]]` |
| `partial` | 一部だけ残す（④ で入れる） | `{ treatment: 'partial', kind: 'email', display: 'a***@e***.com' }` | `a***@e***.com` |
| `alias` | ホスト名を別名にする | URL の文字列の中だけ | `site-1.invalid` |
| `kept` | 残す。上限を超えた分は切り、末尾に `…` を付ける。中には「残す値の中にかける検査」をかける | `{ treatment: 'kept', text: '…' }` | 入力した文字 |
| `dropped` | 記録しない（欄ごと無い） | — | — |

- **保証の強さ**
  - **構造**: 経路・欄の型（`type`・`autocomplete`・タグ）・解析した構造・列挙・形の許可リストで、扱いが必ず決まること。保証するのは「決めた扱いが当たること」で、「残した値に機微な情報が無いこと」ではない（許可した形の中に短いトークンがあっても、それは許可した形の範囲）。出口の独立した検査（E2）は、この種類のものを確かめる。
  - **規則**: 版を固定した語彙と正規化の規則（`shared/sanitize.js` の `classifyField` の一覧、利用者の登録語）に**一致した入力**に、決めた扱いが当たること。content script と worker が同じ関数で判定する。出口の独立した検査は語彙を持たないので確かめない（E2）。一覧に無い同義語・言い換えは「できる限り」。
  - **できる限り**: 残す値の中を、伏せる形の拒否リスト（値の形のパターン）で探す。漏れは既知の限界。
  - **対象外**: 扱わない。下に書く。
- **実装**: ② = この表を入れた PR。③ = URL・ホストの正規化と商用の URL 規則。④ = できる限りの検出の拡充。③・④ の行は、それまで「暫定」の扱いになる。暫定は目標と同じか、より厳しい。より緩い場合は、そう書く。

## 正規化（「できる限り」の検出の前に 1 回だけ。④ で入れる）

- NFKC（② から）
- 書式文字（`\p{Cf}`）と異体字セレクタを取り除く（② は一部の不可視文字だけ）
- 他の文字体系の数字を ASCII に
- ダッシュ類（`\p{Pd}`）を `-` に
- `%` を、解けるところまで 3 回解く（4 回以上は値ごと `[[v]]`）

この後の文字列にない書き方は、できる限りの側です。

## 対象外

## 重大度と収束の条件（レビュー）

- **BLOCKER・HIGH**（どれも「構造」「規則」の行についてだけ）:
  - 実装が ② 以前の「構造」の行の扱いにならない入力がある。
  - 「規則」の行で、一覧にある語（とその正規化の範囲の表記）に一致する入力が、決めた扱いにならない。
  - 「構造」「規則」の行の退行。
  - 出口・受信の構造の検査（E1〜E3）を通らないはずのものが通る。
  - 「できる限り」の行でも、固定した資料（下）にある反例の退行。
- **MEDIUM**: 「できる限り」の行の検出漏れ。「規則」の行で、一覧に無い同義語・言い換えが当たらないこと（語の追加は ④ で検討）。出口まで届く漏れでも、その値が「できる限り」の行で残ったものなら MEDIUM（層をまたいだことでは HIGH にしない）。既知の漏れの一覧に積む。
- **範囲外**: 「実装」が後の PR の行の、目標との差（暫定の扱いどおりなら指摘しない）。
- **収束**: 次をすべて満たすこと。
  - この表の範囲で BLOCKER・HIGH が 0。
  - 回帰用の資料と性質の検査が、すべて通る。資料は PR を始めた時点の `tests/fixtures/` の反例の集合で固定する（資料を作るまでは、この条件を除く）。
  - レビューで出た「構造」「規則」の行の反例は、その PR で直して資料に足す。「できる限り」の行の反例は既知の漏れの一覧に足し、その PR の収束の条件には入れない。
  - 最後の修正の後に、確認のラウンドを済ませている。
- **上限**: 1 つの PR につきレビューは最大 10 ラウンド。上限に達したら、その PR のレビューは終える（上限は上げない）。続けるかどうかはオーナーが決め、続けるなら直すものを絞った別の PR にする。
- 指摘を直すのにこの表を変える必要があるときは、ラウンドを続けずにオーナーに返す。
