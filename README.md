# op-scribe

Chrome でのブラウザ操作を記録し、**個人情報・社内情報を伏せたうえで**、次の 3 つにまとめる Chrome 拡張です。

| 出力 | 読み手 | 中身 |
| --- | --- | --- |
| 簡易手順（Markdown） | 人 | 「〜をクリックする」形式の再現手順。オンデバイス AI で読みやすく整える |
| Gherkin + 属性表 | AI・自動化 | `Given` / `When` / `Then` の手順。各ステップに画面 URL や対象要素（role・name・selector）の表が付く |
| 操作記録データ（JSON） | プログラム | 上の 2 つと全ステップ。確認してから任意の送信先へ送れる |

不具合報告の再現手順づくり、テストシナリオの下書き、AI エージェントへの操作の引き継ぎに使えます。

記録処理はページの操作を受動的に観測します。既定動作やイベント伝播を止めず、フォーカス・入力値・ページの DOM を変更しません。記録側で失敗しても、利用者の操作はそのまま続きます。

- 出力形式の詳細: [docs/FORMAT.md](docs/FORMAT.md)
- 何を伏せて何を残すか: [docs/PRIVACY.md](docs/PRIVACY.md)

## 今できること

AI が無くても、記録から手順を作り、伏せ忘れを検査して持ち出すところまで一通り動きます。AI は手順の文を読みやすくするときと、ページ上の AI エージェントと連携するときにだけ使います。

| できること | AI が無くても動くか | 補足 |
| --- | --- | --- |
| 1 つのタブでの操作の記録（クリック、文字入力、プルダウン、チェックボックス、ファイル選択、Enter / Esc キー、フォーム送信、画面遷移） | 動く | ページの動作を妨げない受動的な記録。別サイトへ移ったら、サイトごとに記録を許可する |
| 操作の直後にページが出した通知（「保存しました」など）の記録 | 動く | 商用環境のホストでは記録しない |
| 入力値・URL・ホスト名を伏せる | 動く | 入力した時点で伏せ、拡張の中でもう一度伏せる。何を伏せるかは [docs/PRIVACY.md](docs/PRIVACY.md) |
| 期待結果と探索メモ（不具合・疑問・気づき・次に試す）を書き足す | 動く | 期待結果は手順の「期待結果」と Gherkin の `Then` になる |
| 簡易手順（Markdown）を作る | 動く（テンプレート） | オンデバイス AI があれば「AI で整理」で読みやすくできる。AI の出力は検査を通ったときだけ使う |
| Gherkin + 属性表を作る | 動く | 常に記録から機械的に作る。要素は role と名前、なければ selector で示す |
| コピー・JSON の保存・送信先への送信 | 動く | どの出口でも、外へ出す直前に全文を検査し、伏せ忘れの疑いがあれば止める |
| 手元の受信サーバで送信を試す | 動く | `pnpm receiver`。受信側でも同じ検査をする |
| ページ上の AI エージェントとの連携（WebMCP） | WebMCP が有効な Chrome が要る | エージェントは記録の状態と手順を読み、期待結果を足せる。エージェントのツール呼び出しも記録する |

### まだできないこと

- 新しいタブ・別ウィンドウ・iframe の中の操作は記録しない。
- ダブルクリック・右クリック・矢印キーなど、上の表に無い操作は記録しない。
- 記録した操作を自動で再生する仕組みは無い。Gherkin と属性表を、人や AI エージェント、テストコードに渡して再現してもらう前提。
- バグチケット向け・テスト実施記録向けの書式は検討中。今は簡易手順と Gherkin を元に人が書く。
- 複数の記録を束ねた報告や集計は無い。

## はじめに用意するもの

| 項目 | 必須か | 補足 |
| --- | --- | --- |
| Chrome 138 以降 | 必須 | |
| オンデバイス AI（Gemini Nano） | 任意 | 「AI で整理」に使う。使えない端末ではテンプレートで手順を作る |
| WebMCP が有効な Chrome | 任意 | AI エージェント連携に使う。無効でも記録・手順化・送信はすべて動く |

## インストール

1. このリポジトリを clone（またはダウンロードして展開）する
2. Chrome で `chrome://extensions` を開き、右上の **デベロッパー モード** をオンにする
3. **パッケージ化されていない拡張機能を読み込む** を押し、このフォルダ（`manifest.json` がある場所）を選ぶ
4. ツールバーのパズルアイコンから op-scribe を固定しておくと使いやすい

インストールしただけでは、どのサイトにもアクセスしません。記録を始めるときに、そのサイトだけ許可を求めます。

## 使い方

ツールバーの op-scribe アイコンを押すと、画面右側に Side Panel が開きます。Side Panel には上から
**記録 / 操作ログ / 再現手順 / 出力・送信 / プライバシーと送信先** の 5 つの欄があります。

### 0. 最初に一度だけ: プライバシー設定（推奨）

**プライバシーと送信先** を開いて、必要な項目を設定し **保存** します。設定はこのブラウザにだけ保存されます。

| 項目 | 何を入れるか | 例 |
| --- | --- | --- |
| 商用環境のホスト | 本番のサイト。ここでの自由入力は文字数だけが残る。ここに無いサイト（検証環境など）では入力した文字が残る（個人情報らしい部分は伏せる） | `www.example.com`、`*.example.com` |
| 実名で記録してよいホスト | 記録にホスト名をそのまま残してよいサイト。ここに無いサイトは `site-1.invalid` のような別名になる | `example.com`、`*.example.com` |
| 必ず伏せる語 | 社名・製品名・人名など、絶対に外へ出したくない語。1 行 1 語（2 文字以上。`mail` や `url` のような語も使える） | |
| 送信先 URL | 記録データを送る先。送らないなら空欄でよい | `https://collector.example.com/recordings` |
| Authorization ヘッダ | 送信先が認証を求める場合だけ | `Bearer xxxx` |

### 1. 記録する

1. 記録したいページを開いた状態で、**記録** 欄の **記録開始** を押す
2. 「サイトへのアクセスを許可しますか」と聞かれたら許可する
3. 欄の右上が **記録中** に変わり、ツールバーのアイコンに **REC** と出る
4. 普段どおりに操作する

記録されるのは、クリック、文字入力、プルダウンの選択、チェックボックス、ファイル選択（ファイル名も中身も残さない）、Enter / Esc キー、フォーム送信、画面遷移と、操作の直後にページが出した通知です。
入力した文字は、記録した時点で伏せられます。

| 入力した内容 | 記録に残るもの |
| --- | --- |
| パスワード、認証コード | `[[secret]]` |
| カード番号 | `[[card]]` |
| メールアドレス欄、電話番号欄、氏名・住所欄 | `[[email]]` `[[phone]]` `[[personal]]` |
| 検索欄・プルダウンの選択 | 入力・選択した文字（個人情報らしい部分は伏せる） |
| その他の入力（商用環境のホスト） | `[[text:6]]`（6 文字入力した、という情報だけ） |
| その他の入力（それ以外のホスト） | 入力した文字（個人情報らしい部分は伏せる） |

商用環境のホストと実名で記録してよいホストは、記録を始めたときの設定が最後まで使われます。

**別のサイトに移動したとき**は、Side Panel に「このサイトはまだ記録を許可していないため…」と表示されます。
そのサイトの操作も記録したい場合は **このサイトも記録する** を押してください。押さなければ、そのサイトで記録されるのは画面遷移だけです。

### 2. 記録を整える

**操作ログ** 欄に、記録したステップが一覧で表示されます。

- 不要なステップ（操作ミスなど）や、見せたくない内容を含むステップは、行の右の **×** で削除する
- 「ここで何が表示されるべきか」を残したいときは、下の入力欄に書いて **追加** を押す
  （例: `一覧に検索結果が表示される`）。追加した内容は、手順の **期待結果** や Gherkin の **Then** になる
- 探索テストの気づきは、入力欄の左で **不具合 / 疑問 / 気づき / 次に試す** を選んで追加する。
  手順の **探索メモ** の節と Gherkin のコメントに残り、期待結果や Then にはならない
- 欄の下に、伏せた箇所の件数（例: `伏せた箇所: 自由入力 3 / メール 1`）が表示される

操作が終わったら **記録** 欄の **停止** を押します。

### 3. 再現手順を作る

**再現手順** 欄のボタンを押します。

| ボタン | 動き |
| --- | --- |
| **AI で整理** | 端末内の AI（Gemini Nano）が、重複をまとめて読みやすい手順にする。初回はモデルのダウンロードに時間がかかることがある |
| **テンプレートで生成** | 記録をそのまま 1 ステップ 1 文にする。AI が使えない環境でも常に動く |

どちらを押しても、下の 2 つの欄が埋まります。

- **簡易手順（自然言語）**: 人が読む手順。自由に書き換えてよい
- **Gherkin + 属性表**: AI や自動テスト向けの手順。こちらは AI を通さず、記録から機械的に作る

AI の出力に、記録に無い URL や伏せ字、伏せるべき値が混ざっていた場合は採用せず、自動でテンプレートに切り替えます（理由が表示されます）。手順の抜けや作り話までは検出しないので、AI の文は記録と見比べてください。
欄の右上の表示が **AI: unavailable** などのときは、この端末では AI を使えません。

出力例（Gherkin）:

```gherkin
  Scenario: 記録された操作
    When 「ログイン」リンクをクリックする
      | action   | click |
      | source   | user |
      | url      | https://site-1.invalid/ |
      | role     | link |
      | name     | ログイン |
      | selector | [data-testid="login-link"] |
    Then "https://site-1.invalid/login" に遷移する
      | source | unknown |
      | url    | https://site-1.invalid/login |
```

### 4. 持ち出す・送る

**出力・送信** 欄から選びます。

| ボタン | 用途 |
| --- | --- |
| **Markdown をコピー** | 簡易手順を、Issue やチャットに貼る |
| **Gherkin をコピー** | AI エージェントやテストコードの作成に渡す |
| **JSON を保存** | 記録データ一式をファイル（`rec-….opscribe.json`）で保存する |
| **プレビュー** → **この内容で送信** | 記録データを送信先 URL に送る |

送信は必ずプレビュー画面を経由し、表示された内容そのものが送られます。

**どの出口でも、外へ出す直前に全文を再検査します。** メールアドレスや電話番号らしき文字列、「必ず伏せる語」、
別名に置き換えた実際のホスト名が 1 件でも残っていると中止し、どこに残っているかを表示します。
その場合は、該当するステップを **操作ログ** から削除するか、手順の文章を編集してからやり直してください。

### 5. 片付け

- **破棄** を押すと、記録を消します（元に戻せません）
- 何もしなくても、**ブラウザを閉じると記録は消えます**（記録はメモリ上にだけあり、ディスクには書きません）

## 送信先を用意する

送信先は、JSON を受け取る `POST` エンドポイントなら何でも構いません。

- 本文: `Content-Type: application/json`。形式は [docs/FORMAT.md](docs/FORMAT.md) の「送信ペイロード」
- 成功の判定: 2xx を返せば「送信しました」と表示される
- URL は `https://`、または手元で試す場合の `http://localhost` / `http://127.0.0.1` に限る

### 手元で試す

同梱の受信サーバを使えば、外部サービス無しで送信を試せます。

```bash
pnpm receiver
# → op-scribe receiver on http://localhost:8787/recordings
```

1. 送信先 URL に `http://localhost:8787/recordings` を設定して **保存**
2. **プレビュー** → **この内容で送信**
3. 受け取ったデータが `recordings/` フォルダに保存される（このフォルダは git に入らない）

受信サーバ側でも伏せ忘れを検査し、見つかった場合は 422 を返して保存しません。
`OPSCRIBE_TOKEN=任意の文字列 pnpm receiver` で起動すると、`Authorization: Bearer 任意の文字列` が無い送信を拒否します。

## AI エージェントと連携する（WebMCP）

WebMCP が有効な Chrome では、記録中のページに次のツールが登録され、ページ上で動く AI エージェントから呼べます。

| ツール | 内容 |
| --- | --- |
| `opscribe_recording_status` | 記録中かどうか、このサイトで何ステップ記録したか |
| `opscribe_get_reproduction` | このサイトでの手順（Markdown と Gherkin）と、このサイトで足したメモ。他サイトのステップとサイドパネルで書いたメモは返さない |
| `opscribe_add_expectation` | 直前のステップに期待結果を追記する |

また、エージェントがページ側の WebMCP ツールを呼び出すと、その呼び出しも `agent` の印付きで記録されます。
これは**記録開始後に読み込んだ（または再読み込みした）ページ**に限ります。記録開始時にすでに開いていたページでは、
ページ側のツールが先に登録済みのため、呼び出しを捕捉できません。

WebMCP は現在フラグの裏にあります。次のオプションを付けて Chrome（Canary）を起動してください。

```bash
open -a "Google Chrome Canary" --args --enable-features=WebMCP,WebMCPTesting
```

## うまくいかないとき

| 症状 | 原因と対処 |
| --- | --- |
| **記録開始** が押せない、または押しても何も記録されない | `chrome://` のページや Chrome ウェブストアなど、拡張が触れないページを開いている。通常の http / https のページで押す |
| 操作しても **操作ログ** が増えない | 別サイトへ移動していないか確認する。移動していれば **このサイトも記録する** を押す |
| 「このページの記録を確認しています」が消えない | 開いているページに記録の仕組みが届いていない。別サイトなら **このサイトも記録する** を押し、そうでなければページを再読み込みする |
| 新しいタブで開いたページの操作が記録されない | 記録するのは開始したタブだけの仕様（`target=_blank` のリンクも同じ）。同じタブで開き直すか、そのタブで記録を始める |
| ページ内の一部（埋め込み枠の中）の操作が記録されない | iframe の中の操作は記録しない仕様 |
| 入力した文字が `[[text:6]]` になって内容がわからない | 「商用環境のホスト」に登録したサイトでの仕様。本番のデータを外に出さないため、内容は残さない |
| 送信やコピーが「伏せ忘れの疑い」で止まる | 表示された箇所を **操作ログ** から削除し、**再現手順** を作り直す（手順の文に残っていると止まったままになる）。ボタン名などに人名が出るサイトは「必ず伏せる語」に登録する |
| 「記録が変わったため、この再現手順は出力できません」と出る | 手順を作った後にステップを削除・追加した。**テンプレートで生成** か **AI で整理** で作り直すか、手順の欄を空にする |
| 「送信先が未設定です」と出る | **プライバシーと送信先** で送信先 URL を設定して **保存** |
| **AI で整理** を押してもテンプレートになる | 表示された理由を確認する。AI を使えない端末、または AI の出力が検査を通らなかった場合はテンプレートになる |
| 記録が消えた | ブラウザを再起動すると消える仕様。残したい場合は停止後に **JSON を保存** する |

## 開発者向け

```bash
pnpm setup-hooks   # commit / push 時の PII ガードと unit test を有効化（clone 後に必ず実行）
pnpm test          # プライバシーフィルタと手順生成の unit test
pnpm guard         # 追跡中のファイル全体を PII / secret ガードで走査
pnpm e2e           # 拡張を入れた Chromium で、架空のサイト（*.test）を使って記録と WebMCP を確かめる
pnpm run pack      # dist/ に配布用 zip（拡張に必要なファイルだけ。`pnpm pack` は pnpm 組み込みの別コマンド）
pnpm receiver      # 動作確認用のローカル受信サーバ
```

拡張そのものに外部依存はなく、ビルドも不要です（素の JavaScript）。E2E だけ Playwright を使います（初回に `pnpm install` と `pnpm exec playwright install chromium`）。WebMCP は Chrome ではまだフラグの奥にあるので、E2E ではページの `document.modelContext` をテスト用の差し替えで用意しています（`e2e/fixtures.mjs`）。

E2E の依存はロックファイルを置かずに `package.json` で版を固定しています。ロックファイルの「名前と版を `@` でつないだ」書き方は、PII ガードのメールアドレス検出に当たるためです（ガードはコミットごとに見るので、一度コミットすると履歴をまとめ直すまで CI が通りません）。pnpm は CI と同じ版（10.34.4）を使ってください。版が固定されていない依存を足すときは、ガードを緩めず、ロックファイルの書き方だけを除く仕組みを先に用意してください。コードを変えたら `chrome://extensions` で op-scribe の再読み込みボタンを押し、記録したいタブも再読み込みしてください。

### 公開リポジトリとしての注意

このリポジトリは公開を前提にしています。clone したら、社名・社内ホスト名・自分の実名などを
`scripts/pii-guard.patterns.local.txt`（git に入らないファイル）に書いてください。書き方は
[`scripts/pii-guard.patterns.local.example.txt`](scripts/pii-guard.patterns.local.example.txt) にあります。
これらの語を、リポジトリ内のファイル（禁止語リストを含む）に書いてはいけません。

テストやドキュメントの例には `example.com` / `*.invalid` / `*.test` だけを使います。詳しくは [docs/PRIVACY.md](docs/PRIVACY.md)。

### 構成

| パス | 役割 |
| --- | --- |
| `shared/sanitize.js` | プライバシーフィルタ（全コンテキスト共通）。入力欄の分類、型の付いた伏せ結果、パターン検出、URL の別名化、最終検査 |
| `shared/record.js` | worker で届いた操作を記録のステップにする。環境（商用かどうか）の判定と再サニタイズ |
| `shared/describe.js` | 手順化（自然言語・Gherkin）。伏せ字 `[[…]]` はここで描画する |
| `shared/payload.js` | 送信データ（v3）の形の唯一の定義。組み立てと、出口・受信サーバの構造の検査 |
| `content/recorder.js` | ページ内で操作を拾う（ISOLATED world）。入力値はここで伏せる |
| `content/webmcp-tools.js` | WebMCP ツールの登録とページ側ツール呼び出しの記録（MAIN world） |
| `service-worker.js` | 記録状態の管理、二重サニタイズ、WebMCP 要求への応答 |
| `sidepanel/` | 操作 UI、オンデバイス AI での整形、プレビュー・送信 |
| `tools/receiver.mjs` | 動作確認用のローカル受信サーバ |
| `scripts/pii-guard.sh` | commit / push / CI 共通の PII・secret ガード |
